# 남은 세 바이옴의 지형 — 구현 계획

> 작업 단위마다 실패하는 테스트 → 구현 → 검증 4종 → 커밋. 진행은 체크박스(`- [ ]`)로 표시한다.

**Goal:** 설원·바람 고원·황무지에 각자의 지형을 준다. 불탄 숲의 용암과 늪지의 늪은 이미 있다. 다섯 곳에서 **움직이는 방식이 각각 달라야** 한다는 스펙의 약속을 마저 지킨다.

**Architecture:** 지형은 세계가 씨앗에서 만드는 고정물. 효과는 순수 함수. 렌더링만 `scenes/play.py`에.

**Tech Stack:** pygame-ce, Python >= 3.10, pytest + pytest-cov, ruff, mypy (strict)

**Spec:** `docs/specs/2026-08-29-world-rebuild-concept-design.md` 「다섯 바이옴」

**선행:** 1~7단계 + 생존 완료

## Global Constraints

- 로직은 순수 `update(dt, ...)`, 렌더링은 `draw(surface)`.
- `config.py`는 pygame을 import하지 않는다.
- 고정 타임스텝 `FIXED_DT = 1/60`. 난수는 주입한다.
- TDD: 실패하는 테스트 → 최소 구현 → 리팩터.
- 명령어: `./.venv/Scripts/python.exe -m pytest` · `-m ruff check . && -m ruff format --check .` · `-m mypy`
- 각 작업의 마지막 단계는 커밋이다.

## 왜 지금인가

스펙은 다섯 지형이 **겹치지 않는다**고 약속했다 — 정적 위험 / 시야 제한 / 낙하 / 이동 저하 / 엄폐 없음. 둘만 있으면 그건 약속이 아니라 두 가지 사례다.

그리고 **보스전이 지형 위에서 벌어진다.** 바람 보스의 밀어내기는 절벽이 있어야 무섭고, 번개 보스의 표식은 숨을 데가 없어야 위협이다. 지형을 먼저 깔아야 보스를 거기에 맞춰 설계할 수 있다. 나중에 깔면 보스를 다시 잡아야 한다.

## 이미 있는 것 (본보기)

| 바이옴 | 지형 | 꼴 |
|---|---|---|
| 불탄 숲 | 용암 웅덩이 | 원 N개, 씨앗 재현, 안에 있으면 초당 피해 |
| 늪지 | 늪 | 원 N개, 씨앗 재현, 움직이면 스테미나·바닥나면 피 |

세 번째도 같은 꼴(바람 고원의 절벽)로 가고, 나머지 둘은 **원이 아니다** — 눈보라도 모래바람도 바이옴 전체에 걸리고, 시계에서 나온다.

다섯이 서로 다른 것을 한다:

| 바이옴 | 무엇이 어려워지나 |
|---|---|
| 불탄 숲 | 길이 막힌다 — 보이는 자리를 피해 돈다 |
| 설원 | 안 보인다 — 코앞까지 와서야 안다 |
| 바람 고원 | 떨어진다 — 발밑이 끊긴다 |
| 늪지 | 숨을 빼앗긴다 — 그 자리에 있는 것이 값이다 |
| 황무지 | **벗어나기 어렵다** — 달려도 느리고 숨도 늦게 돌아온다 |

## File Structure

| 파일 | 책임 |

| `entities/chasm.py` | **신규** 절벽 구멍 하나 |
| `world/chasms.py` | **신규** 바람 고원에 배치 |

| `entities/player.py` | 황무지에서는 달리기가 둔하다 |
| `scenes/play.py` | 배선과 그리기 |

### Task 1: 설원 — 눈보라

**Files:** Create `systems/weather.py` · Modify `scenes/play.py`, `config.py` · Test `tests/test_weather.py`(신규), `test_play_scene.py`

**Produces:**
- `weather.blizzard_at(elapsed) -> float` — 0~1, 시계에서 나오는 순수 함수. 돌풍이 왔다 간다
- 설원 안에 있으면 플레이어 주위 `SIGHT_RADIUS`를 넘어서는 흰 장막
- 세기에 따라 반경이 줄었다 늘었다 한다

**핵심:**
- 시계에서 나오므로 **씨앗 없이도 재현된다**. 난수를 쓰면 돌풍이 매 프레임 튄다
- 피해도 소모도 없다. **보이지 않는 것만으로** 충분하다 — 골렘이 코앞에서 나타난다
- 가장자리 나침반은 계속 보인다. 그게 눈보라의 대응책이다

**테스트로 못박을 것:**
- 설원 밖에서는 장막이 없다
- 세기가 0~1을 벗어나지 않는다
- 같은 시각이면 같은 세기
- 돌풍이 실제로 오르내린다 (상수가 아니다)

- [x] **Step 1~5:** 테스트 · 구현 · 손으로 확인 · 검증 · 커밋 `feat(world): blow a blizzard across the snowfield`

### Task 2: 바람 고원 — 절벽

**Files:** Create `entities/chasm.py`, `world/chasms.py`, `systems/falling.py` · Modify `scenes/play.py`, `config.py` · Test `tests/test_chasm.py`(신규)

**Produces:**
- `Chasm(pos, radius)` — 바람 고원 안에만, 씨앗 재현, 겹치지 않음
- `falling.update_fall(dt, player, chasms)` — 떨어지면 `FALL_DAMAGE`를 입고 **가장자리로 되돌려진다**
- 짐은 잃지 않는다

**핵심:**
- **돌려놓는다, 죽이지 않는다.** 구덩이는 밀려 떨어지는 것이 무서운 거지 즉사가 무서운 게 아니다. 바람 보스의 밀어내기가 들어오면 이게 진짜 위협이 된다
- 가장자리가 멀리서 보여야 한다. 밟기 전에 읽혀야 한다
- 용암·늪과 같은 꼴이라 세 번째 지형은 빠르다

**테스트로 못박을 것:**
- 바람 고원 안에만 생긴다
- 떨어지면 피해를 입고 **구덩이 밖**으로 나온다
- 되돌아간 자리가 또 구덩이가 아니다
- 한 번 떨어지면 피해는 한 번이다 (가장자리에서 계속 덜덜 떨지 않는다)
- 짐은 그대로다

- [x] **Step 1~6:** 테스트 · 구현 · 배선 · 손으로 확인 · 검증 · 커밋 `feat(world): open chasms in the wind plateau`

### Task 3: 황무지 — 달릴 수 없고 숨이 늦게 돌아온다

**Files:** Modify `entities/player.py`, `systems/survival.py`, `systems/weather.py`, `scenes/play.py`, `config.py` · Test `test_player.py`, `test_weather.py`, `test_play_scene.py`

**Produces:**
- 황무지에서는 **달리기 배수가 떨어진다** (`WASTELAND_SPRINT_MULT`). 걷기는 그대로
- `weather.sandstorm_at(elapsed) -> float` — 눈보라와 같은 꼴, 다른 주기
- 모래바람이 부는 동안 **스테미나 회복이 느려진다** (`WASTELAND_REGEN_FLOOR`까지)

**핵심:** 다른 넷은 **그 자리**가 위험한데, 황무지는 **벗어나는 것**이 어렵다. 달려서 떼어낼 수 없고, 떼어냈어도 숨이 늦게 돌아온다 — "넓고 평평해 숨을 데가 없다"가 시야가 아니라 **발과 폐**로 번역된 것이다.

늪지와 헷갈리지 않는 이유: 늪은 **빼앗고** 황무지는 **늦게 돌려준다**. 늪은 벗어나면 끝이고, 황무지는 벗어나는 그 일이 느리다.

**테스트로 못박을 것:**
- 황무지에서 달리면 다른 바이옴보다 느리다. **걷기는 똑같다**
- 모래바람이 세면 회복이 느리고, 멎으면 원래대로
- **아무리 세도 회복이 멈추지는 않는다** — 늪이 이미 멈추는 곳이고, 둘이 같으면 하나가 남는다
- 모래바람은 황무지 밖에서는 아무 일도 안 한다
- 세기는 시계에서 나온다 — 같은 시각이면 같은 값

- [x] **Step 1~5:** 테스트 · 구현 · 검증 · 커밋 `feat(world): make the wasteland hard to leave`

### Task 4: 다섯이 다른지 확인한다

**Files:** Test `tests/test_biome_terrain.py`(신규)

**Produces:** 다섯 바이옴을 **나란히 놓고** 비교하는 테스트 한 묶음.

- 다섯이 각각 다른 것을 한다 (한 바이옴의 지형이 다른 바이옴에 새지 않는다)
- 용암은 불탄 숲에만, 늪은 늪지에만, 구덩이는 바람 고원에만
- 눈보라는 설원에서만 걸린다
- 황무지에서만 달리기가 느리고 회복이 늦다
- **초원은 다섯 중 아무것도 하지 않는다** — 안전한 땅이 안전한 채로 남는다

**핵심:** 각 작업의 테스트는 자기 지형만 본다. 이 묶음은 **겹치지 않는다**는 스펙의 약속 자체를 지킨다 — 나중에 지형을 하나 더 넣을 때 새는 것을 여기서 잡는다.

- [x] **Step 1~4:** 테스트 · 실패하면 고치기 · 검증 · 커밋 `test(world): hold the five terrains apart`

## 이 계획이 끝나면

다섯 바이옴에서 움직이는 방식이 각각 다르다. 그 위에 사원과 보스를 올릴 수 있다 — 바람 보스의 밀어내기는 설 절벽이 있고, 번개 보스의 표식은 숨을 데가 없다.

**남는 것:** 사원과 보스 5마리(상위·최상위 그림 10개, 레벨 캡), 최종전과 엔딩, 타일 렌더링(설원 타일 대기).

## 실제로 끝난 뒤의 기록

**흰 땅 위의 흰 눈은 안 보인다.** 눈보라 색을 설원 땅색과 거의 같게 잡아서, 돌풍이 세게
불어도 화면이 달라지지 않았다. 거의 순백으로 올려 고쳤는데 — 더 중요한 건 **눈보라가
가리는 건 땅이 아니라 그 위에 선 것들**이라는 점이다. 그것들은 전부 색이 있으니까.
테스트도 "땅색이 바뀌나"에서 "저만치 있는 광맥이 안 보이나"로 바꿨다.

**투명 원을 여러 개 그려도 그라데이션이 안 된다.** 보이는 범위를 고리로 깎아 부드럽게
만들려 했는데, 각 고리가 앞 고리를 **덮어쓰기** 때문에 결국 구멍 하나가 딱 잘린 모양으로
남았다. 바깥에서 안으로 가며 알파를 낮추는 쪽으로 고쳤다.

**HUD 바탕이 풀밭용이었다.** 검정 알파 90은 녹색 위에서는 충분한데 흰 눈 위에서는 옅은
회색이 된다. 왼쪽 아래 글줄은 바탕이 아예 없어서 흰 글자가 흰 화면에 묻혔다. 165로 올리고
글줄에도 바탕을 줬다 — 나침반 표시가 이미 같은 방법으로 해결한 문제였다.

**구덩이는 프레임마다가 아니라 떨어질 때마다 값을 치른다.** 가장자리에 내려놓는 구조라서,
프레임마다 깎으면 가만히 선 사람이 덜덜 떨다 죽는다.

**황무지와 늪지를 구분하는 선** — 늪은 **빼앗고** 황무지는 **늦게 돌려준다**. 모래바람이
회복을 0으로 만들면 늪과 같은 것이 되고, 그럼 둘 중 하나가 남는다. 바닥을 0.25로 둬서
늪만이 "아무것도 안 돌아오는 곳"으로 남게 했다.

**마지막 묶음이 제 몫을 했다.** 각 지형의 테스트는 자기 것만 보는데, 스펙의 약속은 다섯이
**서로 다르다**는 것이다. 한 세계에 다섯을 올려놓고 "다른 넷은 아무 일도 안 하나"를 물으면
새는 것이 보인다 — 그리고 "다른 바이옴은 전부 똑같은 속도로 달리나"는 한 줄이 나중에
지형을 하나 더 넣을 때를 지켜준다.
